# cli-dbx 修复验证报告（2026-10-03）

此前确认的 8 类问题已修复，并补齐先失败、修复后通过的回归测试。独立审查发现的括号表分组、单引号表名、MERGE 目标和方言 WHERE 边界也已修正、复验。

## 修复项目

| 问题 | 修复后的行为 |
| --- | --- |
| F01：query 隐藏写入 | 写入型 CTE 整体拒绝；EXPLAIN 只接受只读正文；设置 PRAGMA 必须使用 admin；tx 同样检查 |
| F02：内层 WHERE 被误算 | 只检查最外层 UPDATE/DELETE，排除字符串、注释、CTE 和子查询条件 |
| F03：表白名单遗漏 | 引号、注释、CTE 作用域、USING 来源、括号关系、SQLite 单引号表名和 MERGE 目标共同校验 |
| F04：SQL Server 新密码泄漏 | userinfo 与 change password 等密码参数在展示及错误中掩码，处理编码、大小写、多值及重叠密码 |
| F05：同名结果列丢值 | 生成不冲突的列名后缀，列、行和内部统计保持一致；普通列名保留 |
| F06：JSON 大整数舍入 | 先保留数字文本；int64 整数精确绑定，超界和高精度数字以原始文本绑定 |
| F07：SQLite VACUUM 失败 | admin 使用已有非事务执行路径；update/schema/import/tx 的事务保护继续保留 |
| F08：格式错误发生于写入后 | 连接解析、数据库操作及导出文件创建之前校验格式；非法格式退出 1，没有写入或截断副作用 |

## 兼容性和实测范围

- 写入型 CTE、对写语句的 EXPLAIN 暂整体拒绝；未知或可能修改状态的 PRAGMA 需要 admin。
- 普通引号内反斜线、MySQL `#` 行注释、Oracle/达梦 `q/nq` 替代引号及 PostgreSQL 数组下标暂保守拒绝。支持标准重复引号、SQL Server 方括号、PostgreSQL dollar quote 和显式 E 字符串。可以用标准注释、普通引号或字符函数改写不支持的形式。
- admin 不承诺 `--max-rows-affected` 超限回滚。JSON 精确文本传入数据库后，最终精度仍取决于目标列类型。
- 本轮未连接真实厂商数据库，未实测系统凭据库、Windows/Linux 运行或 Platform 安装。SQLite ODBC 使用 SQL Server 标签只验证执行与传输管道，不能作为真实 SQL Server/Oracle/达梦兼容性验收。
- SQL 保护是保守的词法和结构检查；数据库函数本身的副作用仍由数据库权限约束。ODBC fork 的 6 处既有静态警告也没有在本轮 8 类修复中改动。
