测试版本：`v0.2.0-driver-process.3`。现有自动测试通过，但补充功能测试发现 8 类可复现问题，ODBC fork 静态检查另有 6 条告警。当前版本不能记为全功能验收通过。

## 3. 当前功能的覆盖情况

| 功能 | 已执行 | 仍需手动验证 |
| --- | --- | --- |
| `version`、帮助、错误参数 | 全部公开命令入口及已列举的参数错误路径 | 安装后命令路径、不同 Shell 的 quoting |
| `conn list/show/test` | 配置来源、环境变量 DSN、脱敏、SQLite 连接、原生错误连接、ODBC 替身连接 | 真实登录、TLS、认证选项、网络错误 |
| `inspect connection/schema/table` | SQLite 元数据、键、表结构 | 各数据库 schema/catalog、大小写、权限、视图、厂商目录 |
| `query` | JSON/table/verbose、Unicode/NULL/binary、空结果、分页、文件及临时 DSN | 厂商日期、时区、LOB、精确 DECIMAL、真实大结果 |
| `update` | 增删改、策略、最大影响行数与回滚 | 厂商 MERGE、账号权限、并发与连接中断 |
| `schema` | SQLite 建表、索引、ALTER、RENAME、DROP，file/dsn 子命令实际执行 | 厂商 TRUNCATE 和 DDL 提交语义 |
| `admin` | SQLite ANALYZE，file/dsn 子命令实际执行；VACUUM 复现失败 | 厂商 GRANT/REVOKE/SET、VACUUM 及所需权限 |
| `import/export` | CSV/JSON、Unicode 参数、导出限制、dry-run、整批回滚；CSV 逗号/引号/换行往返，输出路径失败和已有文件行为 | 厂商类型绑定、编码、超大文件 |
| `tx` | dry-run、提交、语句失败回滚、行数超限回滚、只允许 query/update；尾随 JSON 行为 | 厂商隔离级别、死锁、提交时断线与结果不确定 |
| 策略 | allow_actions、allow_tables、普通缺少 WHERE、多语句、生产环境限制、启动子进程前拒绝 | 第 4 节绕过案例的修复回归 |
| 密码 | 畸形 v1/v2 密文、禁止来源及内存替身单元测试 | 真实 Keychain/Credential Manager/Secret Service、隐藏输入、密钥缺失及迁移 |
| 原生独立驱动 | 包及 manifest、四引擎错误连接、协议单元测试 | PostgreSQL/Oracle/DM/SQL Server 真库的全部操作 |
| ODBC 独立驱动 | Mac ARM64 unixODBC + SQLite 厂商替身；移动目录、空格路径、无 DYLD 覆盖、参数 Unicode、NULL、binary、事务、导入导出、7 类 manifest 拒绝、超时和 SIGINT 后子进程回收 | 三个真实厂商驱动；Windows/Linux 运行；精确类型及元数据 |
| Platform 连接器 | 发布包内容、CLI/技能版本和依赖隔离 | 真实部署、加载及配置权限 |

当前 `readonly` 是描述信息；实际动作限制由 `allow_actions` 和数据库账号权限承担。本次不把该字段未拦截写入计为缺陷。临时 DSN 拥有独立策略，也不能当成命名连接策略的继承入口。

补测观察：`export` 会截断并覆盖已存在且可写的输出文件；不可写文件/目录和不存在父目录返回失败。`tx --plan` 读取第一段 JSON 后忽略第二段完整 JSON，应确保计划文件只有一个对象。SQL 文件和临时连接使用 `schema/admin file …`、`schema/admin dsn …` 子命令；`--file`、`--dsn` 不是当前参数。详见 `results/delivery-extra.json`、`results/native-extra.json`。

ODBC 替身为历史 SQLite ODBC 0.99991。其 ANSI-only 构建在 SQL 中文字面量插入时产生无效 UTF-8 字节；参数导入和预置 UTF-8 读取复测通过。这个 fixture 限制不归因于 DBX，也不能据此认定真实 ODBC Unicode 验收通过。SQLite 替身的数值元数据无法代替厂商 DECIMAL 元数据。

## 4. 已复现问题

| 编号 | 问题 | 实际结果与证据 |
| --- | --- | --- |
| F01 | query 分类接受潜在写入 | 写入 CTE、`EXPLAIN ANALYZE DELETE`、写入 PRAGMA，以及 tx query 步骤中的写入 CTE 被 dry-run 接受。厂商语义只做策略验证，未连接 PostgreSQL 执行。`results/safety.json`：write-cte-query / explain-analyze-write / pragma-write-query / tx-hidden-write |
| F02 | WHERE 校验未限定在外层写语句 | CTE、子查询或字符串中的 WHERE 可使外层全表 UPDATE/DELETE 通过。临时 SQLite 上实际删除了全部 3 行。`results/safety.json`：cte-inner-where / subquery-inner-where / literal-where / cte-inner-where-execution |
| F03 | 表白名单提取不完整 | 字符串内 `/*` 与 `USING` 来源表可以绕过检查；临时 SQLite 实际读到了白名单外的合成 token。`results/safety.json`：literal-comment-table / delete-using-table / merge-using-table / literal-comment-table-execution |
| F04 | SQL Server DSN 新密码没有脱敏 | `conn show` 保留 `change password=NEW_DUMMY_SECRET`；本次只用假密码。`results/safety.json`：sqlserver-change-password-secret |
| F05 | 重复结果列丢值 | `SELECT 1 AS id, 2 AS id` 的 rows 只保留 `id:2`。`results/safety.json`：duplicate-result-columns |
| F06 | JSON 大整数导入精度丢失 | `9007199254740993` 导入后变为 `9007199254740992`。`results/safety.json`：large-int-json-import-roundtrip |
| F07 | SQLite VACUUM 无法执行 | `dbx admin … vacuum` 报 `cannot VACUUM from within a transaction`。`results/core-smoke.json`：admin-vacuum |
| F08 | 输出格式错误在提交后才返回 | `update … --format unsupported` 返回 exit 1，但随后的 query 确认数据已经提交。`results/edges.json`：invalid-output-format-commits-write |

ODBC fork 静态检查另外报告：`api/zapi_unix.go:64:65`、`conn.go:57:9`、`driver.go:26:8`、`driver.go:68:8`、`handle.go:16:11`、`odbcstmt.go:92:8`。这些是可能误用 `unsafe.Pointer` 的诊断，本次没有证实对应运行故障，不并入上述 8 类功能缺陷。

已保留最初测试夹具错误和修正记录：release snapshot 误排除 cmd/dbx、smoke 参数/清理断言、ODBC TOML 语法、取消观察方法等。更正夹具后已重测；这些不记为产品失败。
