# DBX 新增数据库连接器技术选型

> 历史讨论记录：其中自定义 Connector、进程协议及 ODBC 自动回退方案不再采用。当前六种通用数据库驱动内置，OceanBase 仅考虑 MySQL 模式，TDSQL 仅考虑 MySQL／PostgreSQL 兼容模式；Windows ARM64、macOS Intel 和 OceanBase Oracle 模式暂不支持。其他数据库可显式使用通用 ODBC，见 [ODBC 说明](odbc.md)；本文不作为当前开发指令。

> 2026-09-23 补充：纯 Go / ODBC 对比表、数据库平台支持表及当前调用树图统一维护在 [ODBC 说明](odbc.md)。本文旧表中的 OceanBase Oracle 模式 Go 驱动支持结论尚需核实，不应作为已确认能力。

> 范围：Oracle、达梦、SQL Server、OceanBase；不讨论已有 MySQL、PostgreSQL、SQLite。

## 1. 选型结论

| 数据库 | 当前方案 | 官方方案 | 推荐 |
|---|---|---|---|
| Oracle | 社区 `sijms/go-ora/v2` | `oracle/go-oracledb/v26` | 当前保留社区版；官方版稳定发布、本机构建工具链从 Go 1.26.4 升至 1.26.6 且只需 Oracle 19c+ 后再切换 |
| 达梦 | 社区镜像 `gitee.com/chunanyong/dm` | 安装介质中的 `dm-go-driver` | Windows/Linux 生产优先官方包；macOS 需厂商提供可编译版本 |
| SQL Server | 微软 `microsoft/go-mssqldb` | 同左 | 已是官方方案，保持不变 |
| OceanBase MySQL | 复用 `go-sql-driver/mysql` | 官方文档也推荐该社区驱动 | 保持不变 |
| OceanBase Oracle | `oceanbase/go-oceanbase-driver` | 同左 | 已由 OceanBase 官方组织维护，保持不变 |

### 官方与社区方案比较

| 数据库 | 社区方案 | 官方方案 | 官方方案代价 | 结论 |
|---|---|---|---|---|
| Oracle | `go-ora`：支持 10.2+、纯 Go；供应链不归 Oracle | `go-oracledb/v26`：Oracle 官方、纯 Go、支持 19c+ | 官方驱动要求构建工具链 Go 1.26.6；本机当前为 1.26.4；需改 DSN、错误处理并重测 | 有 11g/12c 时保留社区版；仅支持 19c+ 后切官方版 |
| 达梦 | `chunanyong/dm`：可直接 `go get`；来源未经达梦背书 | `dm-go-driver`：达梦官方包 | 需内部托管；已取官方包在 macOS 编译失败 | Windows/Linux 生产选官方包；跨 macOS 发布暂不能直接替换 |
| SQL Server | 旧社区仓库已转向微软维护分支 | `microsoft/go-mssqldb`：官方、纯 Go、不依赖 ODBC | 无 | 直接使用官方版 |
| OceanBase MySQL | `go-sql-driver/mysql`：社区维护 | 官方文档采用同一驱动 | 需验证 OceanBase 方言和元数据 | 作为厂商推荐方案使用 |
| OceanBase Oracle | 无更合适的通用社区方案 | `oceanbase/go-oceanbase-driver`：官方组织维护 | 需企业版 Oracle 租户真库验证 | 使用官方版 |

官方驱动降低供应链和厂商支持风险，但仍需验证连接、TLS、schema、元数据、参数绑定、LOB、事务和错误码。

版本说明：本机 `go version` 是 Go 1.26.4；`cli-dbx/go.mod` 中的 `go 1.22` 是项目语言及模块兼容基线，不代表本机安装的是 Go 1.22。Oracle 官方驱动要求的是 Go 1.26.6 构建工具链。

### 社区与官方方案编包大小

下表是单驱动最小程序相对无驱动程序的二进制增量，使用 `CGO_ENABLED=0`、`-trimpath`、`-ldflags "-s -w"`：

| 数据库 | 社区方案 macOS / Windows | 官方方案 macOS / Windows | 说明 |
|---|---:|---:|---|
| Oracle | `go-ora`：+16.44 / +16.77 MiB | `go-oracledb`：**+5.14 / +5.63 MiB** | 官方版小约 11 MiB；实测版本为 v26.0.1-beta、Go 1.26.6 |
| 达梦 | 社区镜像：+5.62 / +6.08 MiB | 官方包：**无法编译 / +6.04 MiB** | 官方 `dm-go-driver` 8.1.2.192 缺少 macOS 安全模块实现 |
| SQL Server | 旧社区版：+3.92 / +4.27 MiB | 微软官方版：+4.15 / +4.54 MiB | 官方版约多 0.2～0.3 MiB，建议接受 |
| OceanBase MySQL | 独立引入：+2.79 / +3.11 MiB | 无独立官方驱动 | DBX 已有 MySQL 驱动，实际新增接近 0 |
| OceanBase Oracle | 无可比社区方案 | 官方版：+2.72 / +3.05 MiB | 直接采用官方版 |

当前接入方案使用“主机、端口、数据库/Schema、用户名、密码，通过 TCP/TLS 直连数据库”时，不依赖 ODBC、JDBC、JRE 或 Oracle Instant Client。达梦配置第三方加密插件时例外，会按需加载 `cipherPath` 指定的动态库。

## 2. 支持范围与跨平台

| 数据库 | 建议支持范围 | macOS | Windows | 当前状态 |
|---|---|---|---|---|
| Oracle | 10.2+；优先验收 11g、12c、19c | 中高 | 中高 | 编译通过，真库待测 |
| 达梦 | DM8；先验收 8.1.4.170 | 中 | 中 | 编译通过，真库与厂商版本待测 |
| SQL Server | 2005+；按客户实际版本验收 | 高 | 高 | 编译通过；SQL Auth 跨平台 |
| OceanBase MySQL | 目标 4.x MySQL 租户 | 中高 | 中高 | 复用已有驱动，真库待测 |
| OceanBase Oracle | 目标企业版 4.x Oracle 租户 | 中 | 中 | 编译通过，真库待测 |

已交叉编译通过：`darwin/amd64`、`darwin/arm64`、`windows/amd64`、`windows/arm64`。编译通过不等于完成数据库兼容认证。

### 动态链接库依赖

| 方案 | 数据库厂商动态库 | 说明 |
|---|---|---|
| Oracle `go-ora` / 官方 `go-oracledb` | 无 | 均为纯 Go，不需要 OCI 或 Oracle Instant Client |
| 达梦社区驱动 | TCP/TLS、用户名密码直连时无 | 仅使用第三方加密插件并设置 `cipherPath` 时，动态加载 DLL/SO/dylib |
| 达梦官方包 | TCP/TLS、用户名密码直连时无 | Windows/Linux 同样支持按需加载第三方加密库；当前官方包无法编译 macOS |
| SQL Server 官方驱动 | 无 | 纯 Go TDS，不需要 Microsoft ODBC Driver |
| OceanBase 双模式 | 无 | Go 驱动直接编入 `dbx` |

“系统自带库”是操作系统预装并维护的基础组件：macOS 的 `libSystem` 提供进程、内存、文件和网络能力，`libresolv` 负责 DNS，CoreFoundation/Security 用于系统基础能力和钥匙串；Windows 的 `kernel32.dll` 提供进程、内存和文件等基础 API。实测当前 `dbx` 只引用这些系统库，不需要随 Connector 分发，`bin/libs` 可保持为空。

## 3. 编译体积影响

完整 DBX 从提交 `b8b7534` 到 `118d5e9`：

| 目标 | 变更前 | 变更后 | 增量 |
|---|---:|---:|---:|
| macOS ARM64 | 12.79 MiB | 29.79 MiB | **17.00 MiB** |
| Windows AMD64 | 13.56 MiB | 30.67 MiB | **17.11 MiB** |

社区与官方驱动的单项体积见“选型结论”。这些数据不能相加，Go 链接器会复用依赖并删除未使用代码。

## 4. 可选 Connector 方案（待实施）

基础 `builtin.dbx` 维持提交 `b8b7534` 的 MySQL、PostgreSQL、SQLite 能力；新增数据库作为依赖它的外置扩展 Connector：

```text
dbx.oracle       # Oracle
dbx.dameng       # 达梦
dbx.sqlserver    # SQL Server
dbx.oceanbase    # OceanBase MySQL/Oracle 双模式
```

外置包安装在：

```text
zenmind-env/connectors-center/
├── dbx.oracle/
├── dbx.dameng/
├── dbx.sqlserver/
└── dbx.oceanbase/
```

用户仍执行统一的 `dbx` 命令。基础 DBX 完成配置读取、密码解密、权限及 SQL 安全检查，再调用对应 Connector。每个 Connector 负责驱动、DSN、方言、元数据和 SQL 执行，不重复携带 `builtin-dbx` Skill。

扩展 Connector 通过清单声明关系：

```json
{
  "id": "dbx.oracle",
  "requires": {"connector": "builtin.dbx", "minVersion": "0.1.2", "protocol": "dbx-driver/v1"},
  "provides": {"dbxEngines": ["oracle"], "dialectProfile": "oracle"}
}
```

Agent 选择扩展 Connector 时，Platform 自动挂载 `builtin.dbx`，并生成包含驱动绝对路径、版本和协议的注册表。基础 DBX 只从该注册表发现驱动，不扫描全局 PATH。扩展未安装时返回明确的安装提示；卸载扩展不影响 `builtin.dbx`。

Platform 从 `connectors-center` 加载外置包，并将选中的扩展与 `builtin.dbx` 一起复制到 `ru-agents/<agentKey>/connectors/`。外置包不进入 `agent-platform/internal/resources/connectors`。

每个可选 Connector 支持：

```toml
backend = "auto" # auto | odbc | embedded
```

`auto` 先检查本机是否存在匹配数据库和 CPU 架构的 ODBC Driver；不存在、架构不匹配或无法加载时，使用 Connector 内置 Go 驱动。ODBC 已加载但连接失败时不自动回退，避免掩盖认证、TLS 或网络错误。执行结果记录实际后端、驱动名称和版本。

仅存在 ODBC Driver Manager 不代表数据库驱动可用。由于 Connector 仍包含 Go 驱动作为兜底，其自身大小不会减少，但基础 DBX 不再承担四种新增驱动的体积。

未来新增数据库只需实现 `dbx-driver/v1` 并声明引擎、方言配置和能力。仅当协议缺少能力，或新方言出现基础 DBX 无法识别的危险 SQL 时，才需要升级 `builtin.dbx`。

## 5. Connector 树图

```text
cli-dbx/                              # DBX 功能和驱动源码
├── cmd/dbx/                          # CLI 入口
├── internal/conn/                    # 引擎、配置与 DSN
├── internal/db/                      # 驱动注册、执行与元数据
├── internal/sqlanalyzer/             # SQL 分类和安全检查
├── scripts/release/                  # 多平台构建
└── go.mod                            # 驱动版本

agent-platform/
└── internal/resources/connectors/builtin.dbx/
    ├── connector.json                # Connector 清单
    ├── cli.json                      # CLI 版本约束
    └── skills/builtin-dbx/           # 随 Connector 内嵌的 Skill

zenmind-env/connectors-center/
├── dbx.oracle/                       # 外置 Oracle Connector
├── dbx.dameng/                       # 外置达梦 Connector
├── dbx.sqlserver/                    # 外置 SQL Server Connector
└── dbx.oceanbase/                    # 外置 OceanBase Connector

发布包/connectors/builtin.dbx/
├── bin/dbx                           # Windows 为 dbx.exe
├── connector.json
├── cli.json
└── skills/builtin-dbx/
```

`cli-dbx` 产出二进制；`agent-platform` 将二进制、Connector 清单和 Skill 装配进发布包。

## 6. 安全要求

- 新增方言必须继续受 `allow_actions`、`allow_tables` 和 SQL 分析器限制。
- 禁止 `SELECT INTO`、多语句及 `SELECT ... FOR UPDATE` 等锁定语句。
- 生产环境使用数据库只读账号；Skill 提示不能替代数据库权限。
