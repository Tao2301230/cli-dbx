# DBX 数据库连接手动测试手册

适用代码：`0401047`，测试平台：macOS Apple Silicon、Windows x64。

目标：验证连接、数据库身份、结构查询、增删改查、参数化导入、导出、事务提交/回滚及基本安全限制。兼容模式需对每个实际产品版本分别执行；一次连接成功不代表所有版本或 SQL 语法都兼容。

## 1. 测试范围与顺序

| 连接名（文件名不含 .toml） | 实际数据库 | engine | driver | 额外客户端驱动 |
|---|---|---|---|---|
| mysql | MySQL | mysql | 省略，内置 | 无 |
| postgres | PostgreSQL | postgres | 省略，内置 | 无 |
| sqlite | SQLite | sqlite | 省略，内置 | 无 |
| oracle | Oracle | oracle | 省略，官方 Go 驱动 | 无 |
| sqlserver | SQL Server | sqlserver | 省略，微软 Go 驱动 | 无 |
| dameng | 达梦 | dm | 省略，社区 Go 驱动 | 无 |
| oceanbase_mysql | OceanBase MySQL 模式 | mysql | 省略，内置 MySQL | 无 |
| tdsql_mysql | TDSQL MySQL 兼容实例 | mysql | 省略，内置 MySQL | 无 |
| tdsql_pg | TDSQL PostgreSQL 兼容实例 | postgres | 省略，内置 PostgreSQL | 无 |
| mysql_odbc | MySQL | mysql | odbc | MySQL Connector/ODBC |

建议先测 SQLite，确认 CLI 操作，再依次测试远程连接；最后测 ODBC。MySQL 原生与 ODBC 可指向同一个测试库，分开完成并清理后再测下一条通路。

以下写入仅针对专用测试库里的 `dbx_manual_items` 表。远程数据库、账号和 schema 需预先准备，账号需具备建表、读写、删表及读取元数据的权限。不要将这些命令指向业务表；同名表已存在时先确认归属，不要直接删除。

## 2. 准备 CLI 和工作目录

使用完整的独立 CLI 发布包。macOS 必须保留 `dbx` 同级的 `lib/` 及许可证目录，不能单独拷贝可执行文件。

解压后进入包含 `dbx` 或 `dbx.exe` 的目录，以下所有命令都在此目录执行。

### macOS（zsh / bash）

```bash
cd "$HOME/Desktop/dbx_test"
chmod +x ./dbx
file ./dbx
ls ./lib
otool -L ./dbx
mkdir -p connections fixtures output
# 固定使用当前目录的 CLI，避免调用 ~/.local/bin 中的旧版本。
dbx() { ./dbx "$@"; }
dbx version
dbx --help
```

### Windows（PowerShell）

```powershell
Set-Location "$HOME/Desktop/dbx_test"
New-Item -ItemType Directory -Force connections, fixtures, output | Out-Null
function dbx { & "$PWD/dbx.exe" @args }
dbx version
dbx --help
```

后续标注为 `text` 的命令块，在定义上述 `dbx` 函数后，两种终端均可逐条执行。不要使用 Windows CMD。

## 3. 准备连接文件与密码

每个连接一个 TOML 文件，一个文件只保留一个 `[connection]`。文件名决定连接名。将下面模板保存为对应文件；地址、端口、用户名、库名和 schema 都需按真实环境替换，端口仅为示例。

对每个需要密码的账号，在测试机器、测试用户下运行：

```text
dbx secret encrypt
```

按提示输入密码，将返回的 `dbx-aes-gcm:v2:...` 替换模板中的 `REPLACE_WITH_ENCRYPTED_PASSWORD`。此字符串不是可用密码。macOS 与 Windows 分别加密，不能直接复用另一台机器的密文。SQLite 不需要密码。

以下模板开放 `query/update/schema` 仅用于完整测试；只测连接与查询时可改为 `allow_actions = ["query"]`，跳过写入步骤。PostgreSQL 的 `sslmode = "prefer"` 需按服务端 TLS 要求调整。

### 3.1 `connections/mysql.toml`

```toml
[connection]
engine = "mysql"
host = "127.0.0.1"
port = 3306
user = "dbx_test"
database = "dbx_test"
password = "REPLACE_WITH_ENCRYPTED_PASSWORD"
timeout = "30s"
allow_actions = ["query", "update", "schema"]
tags = ["dev"]
```

### 3.4 `connections/oracle.toml`


## 4. MySQL ODBC 的额外准备

其他九条通路不需要安装 ODBC 厂商库。DBX 不负责下载或安装 MySQL 驱动。

### 4.1 Windows x64

从 [MySQL 官方下载页](https://dev.mysql.com/downloads/connector/odbc/) 选择适合服务端版本的 Windows x64 MSI，使用厂商安装器完成安装及注册。[官方 Windows 安装说明](https://dev.mysql.com/doc/connector-odbc/en/connector-odbc-installation-binary-windows.html)

```powershell
# 改成刚下载的 MSI 路径；安装过程按系统提示授权。
$Msi = "$HOME/Downloads/REPLACE_WITH_MYSQL_ODBC_X64_INSTALLER.msi"
Start-Process msiexec.exe -ArgumentList @('/i', ('"' + $Msi + '"')) -Wait
Get-OdbcDriver -Platform '64-bit' | Where-Object Name -Like '*MySQL*' | Format-List Name, Platform, Attribute
Get-ChildItem 'HKLM:\SOFTWARE\ODBC\ODBCINST.INI' | Where-Object PSChildName -Like '*MySQL*' | Get-ItemProperty | Select-Object PSChildName, Driver
```

选择一个已注册的驱动，读取 `Driver` 对应的 DLL 完整路径。例如路径为 `C:\Program Files\MySQL\Connector ODBC X.Y\myodbcXu.dll`，则在 `mysql_odbc.toml` 替换这两行：

```toml
driver_dir = 'C:\Program Files\MySQL\Connector ODBC X.Y'
odbc_driver = 'myodbcXu.dll'
```

`X.Y` 和文件名以真实安装结果为准。TOML 单引号可避免 Windows 反斜杠转义。当前 DBX 要求查到的 DLL 路径与同架构 ODBC 注册路径一致，因此不要把已注册 DLL 单独复制到另一个目录。无需另外创建 DSN。

### 4.2 macOS Apple Silicon

DBX 发布包自带 unixODBC 管理器，**不自带 MySQL Connector/ODBC**。厂商库必须是 arm64 且与 unixODBC 匹配。MySQL 官方 macOS 安装说明涉及 iODBC，不能假定下载的 DMG 可直接搭配当前 DBX。[官方 macOS 安装说明](https://dev.mysql.com/doc/connector-odbc/en/connector-odbc-installation-binary-macos.html)

如果已有匹配的驱动库：

```bash
# 填真实文件路径；保留厂商包内配套依赖，不只搬运单个 dylib。
MYSQL_ODBC_LIB="/absolute/path/to/libmyodbcXu.dylib"
file "$MYSQL_ODBC_LIB"
otool -L "$MYSQL_ODBC_LIB"
```

检查包含 arm64，依赖库均存在，且供应方说明其使用 unixODBC。`otool` 只辅助检查，不能独自证明 ABI 兼容。将父目录和文件名分别写入 `driver_dir`、`odbc_driver`；不要在 TOML 中使用 `$HOME` 或 `~` 代替绝对路径。

没有匹配二进制时，可按官方源码构建方式选择 unixODBC。下面是本机构建命令模板；先从官方页面下载适合目标服务端的源码包并解压，再替换源码目录。依赖版本以该源码包的构建要求为准，以下步骤不由 DBX 自动执行。

```bash
brew install cmake unixodbc mysql-client openssl@3
DBX_MYODBC_SOURCE="/absolute/path/to/mysql-connector-odbc-source"
DBX_MYODBC_BUILD="$HOME/dbx-mysql-odbc-build"
DBX_MYODBC_PREFIX="$HOME/.config/dbx/drivers/mysql"
cmake -S "$DBX_MYODBC_SOURCE" -B "$DBX_MYODBC_BUILD" \
  -DCMAKE_OSX_ARCHITECTURES=arm64 \
  -DWITH_UNIXODBC=1 \
  -DODBC_INCLUDES="$(brew --prefix unixodbc)/include" \
  -DODBC_LIB_DIR="$(brew --prefix unixodbc)/lib" \
  -DMYSQL_CONFIG_EXECUTABLE="$(brew --prefix mysql-client)/bin/mysql_config" \
  -DOPENSSL_ROOT_DIR="$(brew --prefix openssl@3)" \
  -DCMAKE_INSTALL_PREFIX="$DBX_MYODBC_PREFIX"
cmake --build "$DBX_MYODBC_BUILD" --parallel
cmake --install "$DBX_MYODBC_BUILD"
find "$DBX_MYODBC_PREFIX" -name '*.dylib'
```

按实际生成的库路径填写 TOML，并重复 `file` / `otool -L` 检查。这是本机安装方案，其 Homebrew 依赖不会自动变成可分发的便携驱动包；编译失败时依据源码 `BUILD` 文件处理，不能视作 DBX 连接测试失败。[官方 macOS 源码说明](https://dev.mysql.com/doc/connector-odbc/en/connector-odbc-installation-source-unix-macos.html)、[构建参数说明](https://dev.mysql.com/doc/connector-odbc/en/connector-odbc-installation-source-unix.html)

### 4.3 检查实际通路

```text
dbx odbc dir
dbx odbc list
dbx conn show --config ./connections mysql_odbc
dbx conn test --config ./connections mysql_odbc
dbx query --config ./connections mysql_odbc "select version(), database(), current_user()"
```

当前 `odbc dir/list` 读取 `DBX_DRIVER_DIR` 或默认目录，不读取某个 TOML 的 `driver_dir`；而且 `list` 只自动识别 Oracle、达梦、SQL Server。**MySQL 未被列出并不代表失败**，其配置必须显式指定 `odbc_driver`，以 `conn test` 和实际查询判断。

## 5. 逐个验证连接和服务器身份（只读）

先列出配置。如果只有其中几种环境，只创建相应文件；不要保留重复的 `[connection]` 或未修改完成的占位配置。

```text
dbx conn list --config ./connections
dbx conn test --config ./connections mysql
dbx conn test --config ./connections postgres
dbx conn test --config ./connections sqlite
dbx conn test --config ./connections oracle
dbx conn test --config ./connections sqlserver
dbx conn test --config ./connections dameng
dbx conn test --config ./connections oceanbase_mysql
dbx conn test --config ./connections tdsql_mysql
dbx conn test --config ./connections tdsql_pg
dbx conn test --config ./connections mysql_odbc
```

预期：每个已配置连接返回 `ok: true`。然后记录实际服务端版本及当前数据库身份：

```text
dbx query --config ./connections mysql "select version(), database(), current_user()"
dbx query --config ./connections postgres "select version(), current_database(), current_schema(), current_user"
dbx query --config ./connections sqlite "select sqlite_version()"
dbx query --config ./connections oracle 'select banner from v$version'
dbx query --config ./connections oracle "select user, sys_context('USERENV','SERVICE_NAME'), sys_context('USERENV','CURRENT_SCHEMA') from dual"
dbx query --config ./connections sqlserver "select @@version, db_name(), schema_name(), current_user"
dbx query --config ./connections dameng 'select * from v$version'
dbx query --config ./connections dameng "select user from dual"
dbx query --config ./connections oceanbase_mysql "select version(), database(), current_user()"
dbx query --config ./connections tdsql_mysql "select version(), database(), current_user()"
dbx query --config ./connections tdsql_pg "select version(), current_database(), current_schema(), current_user"
dbx query --config ./connections mysql_odbc "select version(), database(), current_user()"
```

无权访问版本视图时记录权限限制，并向部署方确认版本，不将这一项单独判成连接失败。OceanBase、TDSQL 还应记录产品名、产品版本、兼容模式及是否经过代理；协议返回的版本号不足以确认产品版本。

## 6. 每个连接执行一轮完整功能测试

本节每次只测一个连接。**按顺序执行**；某个本应成功的步骤失败就先排查，不要继续用后面的数据预期判断。测试用到 4 行数据，不验证大表性能；`--page-size` 也不等于服务端只扫描这么多行。

### 6.1 选择连接、schema 和表名

| C（连接名） | S（schema，按配置调整） | N（测试表名） | CSV |
|---|---|---|---|
| mysql | dbx_test | dbx_manual_items | ./fixtures/rows.csv |
| postgres | public | dbx_manual_items | ./fixtures/rows.csv |
| sqlite | main | dbx_manual_items | ./fixtures/rows.csv |
| oracle | DBX_TEST | DBX_MANUAL_ITEMS | ./fixtures/rows-upper.csv |
| sqlserver | dbo | dbx_manual_items | ./fixtures/rows.csv |
| dameng | DBX_TEST | DBX_MANUAL_ITEMS | ./fixtures/rows-upper.csv |
| oceanbase_mysql | dbx_test | dbx_manual_items | ./fixtures/rows.csv |
| tdsql_mysql | dbx_test | dbx_manual_items | ./fixtures/rows.csv |
| tdsql_pg | public | dbx_manual_items | ./fixtures/rows.csv |
| mysql_odbc | dbx_test | dbx_manual_items | ./fixtures/rows.csv |

macOS 赋值（例：SQLite；其他连接照表换值）：

```bash
C="sqlite"
S="main"
N="dbx_manual_items"
CSV="./fixtures/rows.csv"
T="$S.$N"
```

PowerShell 赋值：

```powershell
$C = "sqlite"
$S = "main"
$N = "dbx_manual_items"
$CSV = "./fixtures/rows.csv"
$T = "$S.$N"
```

Oracle、达梦默认未加引号的标识符会转成大写，因此检查/导入时使用大写表名和 CSV 表头。若达梦实例配置了不同大小写规则，以 `inspect` 返回的实际名称为准调整。`T` 始终包含 schema，避免 SQL 使用默认 schema 而 inspect 使用另一 schema。

### 6.2 建表、插入、查询和结构查看

```text
dbx conn show --config ./connections "$C"
dbx conn test --config ./connections "$C"
dbx schema --config ./connections --dry-run "$C" "create table $T (id integer primary key, note varchar(80), amount decimal(12,2))"
dbx schema --config ./connections "$C" "create table $T (id integer primary key, note varchar(80), amount decimal(12,2))"
dbx update --config ./connections --max-rows-affected 1 "$C" "insert into $T (id,note,amount) values (1,'first',10.50)"
dbx update --config ./connections --max-rows-affected 1 "$C" "insert into $T (id,note,amount) values (2,null,20.25)"
dbx query --config ./connections "$C" "select id,note,amount from $T order by id"
dbx inspect schema --config ./connections "$C" "$S"
dbx inspect table --config ./connections "$C" "$N" "$S"
dbx inspect connection --config ./connections "$C"
```

预期：查到两行，第二行 note 为 NULL，金额分别 10.50、20.25；inspect 包含测试表、3 个字段及 id 主键。类型名称、大小写以及数值的 JSON 表现可能随驱动不同，应核对实际数值。`--dry-run` 只校验 CLI 策略，不证明服务器接受 SQL。

MySQL/兼容实例的测试表需使用支持事务的存储引擎，后续回滚才有意义；建表后检查：

```text
dbx query --config ./connections "$C" "select table_name, engine from information_schema.tables where table_schema = '$S' and table_name = '$N'"
```

这条仅对 MySQL、OceanBase MySQL、TDSQL MySQL、MySQL ODBC 执行；MySQL/TDSQL MySQL 通常应为 InnoDB。OceanBase 若返回兼容字段或不同名称，以实际产品事务语义为准记录。

### 6.3 修改与参数化导入

先准备两份 CSV（只需一次）。macOS：

```bash
printf 'id,note,amount\n3,third,30.75\n4,fourth,40.00\n' > ./fixtures/rows.csv
printf 'ID,NOTE,AMOUNT\n3,third,30.75\n4,fourth,40.00\n' > ./fixtures/rows-upper.csv
```

PowerShell（使用 ASCII，避免 Windows PowerShell 5.1 的 UTF-8 BOM 混入 CSV 表头）：

```powershell
Set-Content -Encoding ASCII ./fixtures/rows.csv @('id,note,amount','3,third,30.75','4,fourth,40.00')
Set-Content -Encoding ASCII ./fixtures/rows-upper.csv @('ID,NOTE,AMOUNT','3,third,30.75','4,fourth,40.00')
```

```text
dbx update --config ./connections --max-rows-affected 1 "$C" "update $T set amount=11.50 where id=1"
dbx import file --config ./connections --dry-run "$CSV" "$C" "$T"
dbx import file --config ./connections "$CSV" "$C" "$T"
dbx query --config ./connections "$C" "select id,note,amount from $T order by id"
```

预期：4 行，id=1 的金额 11.50。导入会实际覆盖驱动的参数绑定通路，不能只做 dry-run。重复执行导入会主键冲突，不要把重复执行误判为兼容失败。

### 6.4 分页与导出

```text
dbx query --config ./connections --page-size 2 "$C" "select id,note,amount from $T order by id"
dbx query --config ./connections --page-size 2 --cursor 2 "$C" "select id,note,amount from $T order by id"
dbx export table --config ./connections --format csv --limit 4 "$T" "$C" "./output/$C.csv"
dbx export table --config ./connections --format json --limit 4 "$T" "$C" "./output/$C.json"
```

预期：第一页 id=1、2，第二页 id=3、4；每个导出文件 4 条记录，CSV 另有一行表头。导出顺序不保证，按 id 比较。查看文件：

```bash
# macOS
cat "./output/$C.csv"
cat "./output/$C.json"
```

```powershell
# PowerShell
Get-Content "./output/$C.csv"
Get-Content "./output/$C.json"
```

### 6.5 事务提交与失败回滚

每切换连接都重新生成计划，因为表名包含本轮 schema。macOS：

```bash
cat > ./fixtures/tx-ok.json <<EOF
```

### 6.6 安全限制及写入超限回滚

以下前四条**应该失败**，逐条查看 JSON，不要用遇错即退出的批处理方式执行：

```text
dbx query --config ./connections "$C" "delete from $T where id=1"
dbx update --config ./connections "$C" "update $T set amount=0"
dbx query --config ./connections "$C" "select id from $T; select id from $T"
dbx update --config ./connections --max-rows-affected 1 "$C" "update $T set amount=0 where id>0"
dbx query --config ./connections "$C" "select id,amount from $T order by id"
```

预期：前三条依次为 `action_mismatch`、`missing_where`、`multiple_statements_blocked`；第四条报告影响行数超限并回滚；最后仍为 12.50、20.25、30.75、40.00。若事务不支持或驱动无法提供所需行数，记录错误，不把写入保护判为通过。

### 6.7 删除与清理

```text
dbx update --config ./connections --max-rows-affected 1 "$C" "delete from $T where id=4"
dbx query --config ./connections "$C" "select count(*) as n, sum(amount) as total from $T"
dbx schema --config ./connections "$C" "drop table $T"
dbx inspect table --config ./connections "$C" "$N" "$S"
```

预期：删除后 n=3、total=63.50；drop 成功；最后 inspect 报表不存在，或返回空结构（部分现有引擎的行为），不可仍显示原来的 3 个字段。不要要求所有引擎的 DDL 影响行数一致。

清理后换第 6.1 节的连接参数，从第 6.2 节再测一轮。MySQL ODBC 完整重复这一轮，不能只验证 Ping。

## 7. 常见失败的定位命令

| 现象 | 优先检查 |
|---|---|
| 启动即 `dyld: Library not loaded` | 是否仍运行旧 dbx；`lib/` 是否随完整包保留；`otool -L ./dbx` |
| `Key 'connection' has already been defined` | 一个 TOML 是否写了两个 `[connection]`；使用不同文件拆分 |
| `secret_key_not_found` | 是否更换机器/系统用户；在当前用户下重新执行 secret encrypt |
| `driver_missing` | mysql_odbc 的 driver_dir + odbc_driver 是否指向真实库文件 |
| `odbc_unavailable` | 当前二进制是否启用 ODBC；普通 macOS go build 不等于含 ODBC 的发布构建 |
| Windows 驱动未注册 | 使用厂商 x64 安装器，确认注册路径与配置路径一致 |
| macOS `Can't open lib` / 架构错误 | 厂商库及间接依赖是否齐全，arm64、unixODBC ABI 是否匹配 |
| 连接成功，inspect 失败 | schema 大小写、元数据权限、兼容产品的系统目录差异 |
| 查询成功，import 失败 | 表头大小写、重复主键、类型转换、参数绑定；记录完整脱敏错误 |
| Oracle 无法连接 | service name 是否误填 SID/schema；官方 Go 驱动版本及数据库版本 |
| 兼容实例不能接受通用 DDL | 记录产品和模式，确认分布键等产品语法要求后调整测试建表 SQL |

针对某一个连接继续定位：

```text
dbx conn show --config ./connections --verbose "$C"
dbx conn test --config ./connections --verbose "$C"
dbx inspect table --config ./connections --verbose "$C" "$N" "$S"
```

输出应脱敏。反馈问题时附 CLI 版本、系统/架构、数据库产品/版本、接入方式、失败命令及错误 JSON，不附真实密码或原始连接配置。
