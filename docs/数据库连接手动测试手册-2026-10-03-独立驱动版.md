日期：2026-10-03。版本：`v0.2.0-driver-process.3`；源码 HEAD `86b18d3` 加当前暂存实现。旧手册保留，本手册不沿用旧版内置驱动或 ODBC 安装方式。

按顺序执行：准备 → SQLite 完整流程 → 配置/密码 → 独立驱动 → 厂商数据库 → 已知失败复查 → 填记录。**本版本仍有已知失败，不能记为全功能通过。**

- [配套目录](../examples/manual-test-2026-10-03/)：配置、CSV/JSON 夹具、SQL、事务计划和预期结果。

- 正常命令：exit 0；策略、数据库、驱动错误通常 exit 1；命令/参数语法错误 exit 2。中断退出码以实测记录，不固定写成 130。
- 每条命令后，macOS 用 `echo $?`，PowerShell 用 `$LASTEXITCODE` 查看退出码；不要使用 `set -e`，负例必须继续检查后置状态。

## 1. 当前连接方式

| 连接 | engine | 接入方式 | 需要安装 |
|---|---|---|---|
| MySQL | mysql | 内置 | CLI |
| SQLite | sqlite | 内置 | CLI |
| PostgreSQL | postgres | 独立原生 | CLI + postgres 包 |
| Oracle | oracle | 独立原生 | CLI + oracle 包 |
| 达梦 | dm | 独立原生 | CLI + dm 包 |
| SQL Server | sqlserver | 独立原生 | CLI + sqlserver 包 |
| OceanBase MySQL | mysql | 内置兼容协议 | CLI |
| TDSQL MySQL | mysql | 内置兼容协议 | CLI |
| TDSQL PG | postgres | 独立 PG 兼容协议 | CLI + postgres 包 |
| Oracle ODBC | oracle | 独立 ODBC | CLI + oracle-odbc 包 + 厂商库 |
| 达梦 ODBC | dm | 独立 ODBC | CLI + dm-odbc 包 + 厂商库 |
| SQL Server ODBC | sqlserver | 独立 ODBC | CLI + sqlserver-odbc 包 + 厂商库 |

实际依赖以当前各模块 `go.mod` 为准：PostgreSQL `pgx/v5 v5.7.2`、Oracle `github.com/oracle/go-oracledb/v26 v26.0.1-beta`（当前确为 Oracle 官方仓库，但已独立分发）、DM `gitee.com/chunanyong/dm v1.8.22`、SQL Server `go-mssqldb v1.8.0`。ODBC 使用仓库的 `drivers/odbc/fork`。

## 2. 准备工作目录

使用独立 CLI 包，不使用 Platform 连接器目录。校验下载包的 SHA-256 与发布清单一致后解压；**当前 MySQL/SQLite 主程序无需同级 lib/，ODBC 的运行库跟随独立适配包。** 下面从仓库复制全新的配套目录，所有测试数据写入副本。

下载包可在单独下载目录校验后解压（替换实际文件名；Windows选择AMD64）：

```bash
# macOS：先cd到下载目录；预期校验OK、tar退出0。
shasum -a 256 -c dbx_v0.2.0-driver-process.3_checksums.txt
tar -xzf dbx_v0.2.0-driver-process.3_darwin_arm64.tar.gz
```

```powershell
# Windows：检查发布校验清单中该zip对应行，预期哈希相同后解压。
Get-FileHash ./dbx_v0.2.0-driver-process.3_windows_amd64.zip -Algorithm SHA256
Get-Content ./dbx_v0.2.0-driver-process.3_checksums.txt
Expand-Archive ./dbx_v0.2.0-driver-process.3_windows_amd64.zip ./dbx-cli-unpacked
```

完整checksums清单包含其他平台时，`shasum -c`会报告未下载文件缺失；应核对本机包对应行，不将其他包未下载误判为本机包损坏。

## 3. SQLite 可执行完整流程

按小节顺序逐条执行。配套 `sqlite-cases.json` 同时列出命令和预期，不需要自己创建数据文件。SQL dry-run 只检查 CLI 策略，不验证数据库 SQL 语法；分页是客户端结果分页，不能据此判断服务端扫描量。

```text

# help: exit 0；显示对应版本或帮助
```

## 4. 配置来源、密码与环境限制

### 4.1 配置优先级

预期：显式 `--config` 只读该来源；默认来源中 `$AP_AGENT_CONFIG_HOME/dbx` 的同名连接覆盖 `~/.config/dbx`。用配套的唯一连接名测试，不修改已有连接。以下只做 `conn show`，不会连接数据库。

macOS：

```bash
DBX_MANUAL_GLOBAL="$HOME/.config/dbx/manual_priority_20261003.toml"
# 此文件若已存在，停止；不要覆盖。
if [ ! -e "$DBX_MANUAL_GLOBAL" ]; then
mkdir -p "$HOME/.config/dbx"
cp ./priority/global.toml "$DBX_MANUAL_GLOBAL"
# 子shell内改变量，不改变当前会话原有AP_AGENT_CONFIG_HOME。
(
  unset AP_AGENT_CONFIG_HOME
  dbx conn show manual_priority_20261003
  export AP_AGENT_CONFIG_HOME="$PWD/priority/agent"
  dbx conn show manual_priority_20261003
  dbx conn show --config ./priority/explicit manual_priority_20261003
)
# 仅在确认上面文件由本轮创建后清理。
rm "$DBX_MANUAL_GLOBAL"
else
  echo "同名配置已存在，整组跳过，不改动它"
fi
```

PowerShell：

```powershell
$GlobalProbe = "$HOME/.config/dbx/manual_priority_20261003.toml"
if (Test-Path $GlobalProbe) { throw '同名配置已存在，请停止' }
New-Item -ItemType Directory -Force "$HOME/.config/dbx" | Out-Null
Copy-Item ./priority/global.toml $GlobalProbe
$OldAgentConfig = $env:AP_AGENT_CONFIG_HOME
try {
  Remove-Item Env:AP_AGENT_CONFIG_HOME -ErrorAction SilentlyContinue
  dbx conn show manual_priority_20261003
  $env:AP_AGENT_CONFIG_HOME = "$PWD/priority/agent"
  dbx conn show manual_priority_20261003
  dbx conn show --config ./priority/explicit manual_priority_20261003
} finally {
  if ($null -eq $OldAgentConfig) { Remove-Item Env:AP_AGENT_CONFIG_HOME -ErrorAction SilentlyContinue } else { $env:AP_AGENT_CONFIG_HOME = $OldAgentConfig }
  Remove-Item $GlobalProbe
}
```

三次均 exit 0，`data.meta.role` 依次为 `global / agent / explicit`。第 3.7 节的坏配置都通过**单文件** `--config` 测试，避免一个非法 TOML 污染整个目录的加载结果。`prod` 当前拒绝配置中的 schema/admin，不等于禁止所有 update。临时 DSN 的策略独立，不能用它验证命名连接的白名单是否生效。

### 4.2 密码及真实系统凭据库（待实测）

```text
dbx secret encrypt
dbx secret encrypt 'DBX_FAKE_PASSWORD_ONLY_20261003'
```

两种方式应 exit 0，返回一行 `password = "dbx-aes-gcm:v2:..."`。第一条终端输入应隐藏回显；第二条仅用上面的假密码，位置参数会暴露到 history/进程列表。测试真实账号只用第一条，把返回的**整行**替换 TOML 的占位 password 行，不能新增第二个同名键；不要将密码、密文或真实配置写入日志/仓库。

用正常配置 `conn test` 验证当前用户能解密并登录；再用另一个操作系统测试用户复制仅含假密码密文的临时配置，预期 exit 1、`secret_key_not_found`（未安装/未解锁凭据库时可能是 `secret_store_unavailable`，应记录环境阻塞）。不要删除现有钥匙串条目来制造故障。不得宣称本次已经验证了真实 Keychain/Credential Manager。
