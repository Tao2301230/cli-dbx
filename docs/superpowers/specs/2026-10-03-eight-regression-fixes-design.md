# 八类测试缺陷修复设计

用户已明确要求修复全量测试中确认的 F01–F08。行为目标以 `docs/cli-dbx全量测试报告-2026-10-03.md` 的八个案例为准；不扩展为新的数据库接入功能。

## 约束

- 在当前 `codex/dbx-driver-process` 工作区修复，保留用户已有暂存修改，不重置、不覆盖 Git index。
- 根模块保持 Go 1.22 和原有驱动进程 v1 协议；不增加厂商依赖或 SQL 解析第三方依赖。
- 使用临时 SQLite、假密码和现有进程测试夹具，真实数据库和系统凭据库仍不宣称完成验收。
- 原始手册、全量测试报告和原始失败日志作为历史证据保留；另存修复验证报告和手动回归补充。
- 不修复未证实运行故障的 ODBC unsafe.Pointer 静态诊断，不提交或发布。

## 实施选择

采用现有控制面上的局部修复。SQL 分类与表提取共享识别字符串、标识符、注释和括号层级的标准库分词，阻止已确认的绕过；不继续叠加不识别词法环境的正则黑名单，也不为本轮引入多方言完整解析器。

## 预期行为

| 问题 | 修复后行为 |
| --- | --- |
| F01 | 带写入的 CTE 不得作为只读 SQL 放行；EXPLAIN ANALYZE 的写入不得被 query 放行；设置型 PRAGMA 不属于 query。无法可靠确认动作的组合语句拒绝执行。只读 CTE/EXPLAIN/元数据 PRAGMA 仍可用。 |
| F02 | UPDATE/DELETE 的 WHERE 必须属于外层写语句；字符串、注释、CTE和子查询中的 WHERE 不满足保护条件。 |
| F03 | 字符串中的注释标记不影响后续 SQL；DELETE/MERGE 的 USING 来源表和带引号的表名纳入 allow_tables 校验。 |
| F04 | SQL Server DSN 的 change password 和已支持的密码参数在连接展示及错误输出中脱敏；只使用假密码测试。 |
| F05 | 查询输出列名唯一，重复列获得确定的数字后缀，不能覆盖真实同名后缀列；原本唯一的列名和值保持不变。列元数据、rows和stats一致，进程传输及table/JSON输出保留全部值。 |
| F06 | JSON 导入不先转 float64；整数至少在 int64 范围内精确保留，无法精确绑定的数值保留精确文本或明确拒绝，不静默舍入。 |
| F07 | admin 使用已有非事务 Execute 通路，使 VACUUM 可执行；update及tx/import的提交前行数保护仍使用事务。 |
| F08 | 输出格式在数据库或文件写入前校验；非法格式返回参数错误，并且没有数据库、文件或驱动启动副作用。export文件格式独立校验。 |

## 验证

每类缺陷先补真实行为回归测试并记录失败，再实现最小修复。完成后运行根模块单测、race和vet，四个原生模块和ODBC模块/fork的测试，以及使用新构建CLI的隔离回归和正常功能流程。ODBC fork原有六条静态诊断单独记录，不能归为本轮新失败。最终审查针对本轮修改与八项行为目标。
