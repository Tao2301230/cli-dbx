# cli-dbx 修复回归手册（2026-10-03）

这是一份新补充手册，旧手册和旧全量测试报告保留。先按[独立驱动版手册](./数据库连接手动测试手册-2026-10-03-独立驱动版.md)检查常规功能，再按本文复测此前的 8 类问题。本文只使用本机合成数据和假密码；PostgreSQL、SQL Server 示例只做策略检查或配置展示。

## 准备

在项目根目录执行；需要 Python 3。下面目录必须不存在，重新测试时换一个新目录。

```bash
python3 examples/manual-test-2026-10-03-fixes/prepare.py /private/tmp/dbx-manual-fixes
DBX="$PWD/dist/testing/2026-10-03-fixes-d44dd2tb/dbx"
FIX=/private/tmp/dbx-manual-fixes
CFG="$FIX/connections"
"$DBX" version
```

也可使用自己从当前源码编译的程序，将 `DBX` 设置为其绝对路径。历史发布包不会自动获得这些修复。

## 逐项检查

| 项目 | 合格标准 | 结果 |
| --- | --- | --- |
| 1. 只读命令隐藏写入 | 写入 CTE、EXPLAIN 写语句被拒绝；设置 PRAGMA 不能走 query | ☐ |
| 2. 外层 WHERE | 只有内层或字符串 WHERE 的 UPDATE/DELETE 被拒绝，3 条原始用户数据保留 | ☐ |
| 3. 表白名单 | 注释字面量、USING、括号关系分组及单引号表名都不能绕过白名单 | ☐ |
| 4. DSN 脱敏 | SQL Server 旧、新假密码均不出现在输出中 | ☐ |
| 5. 同名结果列 | 两个和三个结果值均保留，列名、行和统计一致 | ☐ |
| 6. JSON 大整数 | 9007199254740993 精确保留，超 int64 的文本数字保留原文 | ☐ |
| 7. VACUUM | admin 执行成功，用户数据保留 | ☐ |
| 8. 非法输出格式 | 报错退出 1，行、表、导出文件没有变化 | ☐ |

### 1. 只读命令隐藏写入

```bash
"$DBX" query pg-reader 'WITH removed AS (DELETE FROM users RETURNING *) SELECT * FROM removed' --config "$CFG" --dry-run
"$DBX" query pg-reader 'EXPLAIN ANALYZE DELETE FROM users' --config "$CFG" --dry-run
"$DBX" query all 'PRAGMA user_version=999' --config "$CFG"
"$DBX" query all 'PRAGMA user_version' --config "$CFG"
"$DBX" query all 'WITH selected AS (SELECT id FROM users WHERE id=1) SELECT * FROM selected' --config "$CFG"
```

前两条返回 `unknown_statement`，第三条 `action_mismatch`；`user_version` 仍为 0，最后的只读 CTE 正常返回 id=1。前两条应在启动外部驱动之前拒绝，不能以 `driver_missing` 或连接错误作为合格结果。

### 2. 外层 WHERE

```bash
"$DBX" update writer 'WITH selected AS (SELECT id FROM users WHERE id=1) DELETE FROM users' --config "$CFG"
"$DBX" update writer 'UPDATE users SET active=(SELECT active FROM users WHERE id=1)' --config "$CFG"
"$DBX" update writer "UPDATE users SET name=' where '" --config "$CFG"
"$DBX" query all 'SELECT count(*) AS n FROM users' --config "$CFG"
```

三条写语句返回 `missing_where`；最后 n=3。正常 `UPDATE users SET active=1 WHERE id=1` 应能通过 `--dry-run`。

### 3. 表白名单

```bash
"$DBX" query reader "SELECT (SELECT id FROM users LIMIT 1) AS probe, '/*' AS marker, token FROM forbidden" --config "$CFG"
"$DBX" update pg-writer 'DELETE FROM users USING forbidden WHERE users.id=forbidden.id' --config "$CFG" --dry-run
"$DBX" update pg-writer 'MERGE INTO users USING forbidden ON users.id=forbidden.id WHEN MATCHED THEN DELETE' --config "$CFG" --dry-run
"$DBX" query reader 'SELECT * FROM (forbidden CROSS JOIN users)' --config "$CFG"
"$DBX" query reader "SELECT * FROM users CROSS JOIN 'forbidden'" --config "$CFG"
"$DBX" query reader "SELECT '/*' AS marker FROM users" --config "$CFG"
```

前五条返回 `table_blocked`，禁止输出 `SYNTHETIC_PRIVATE_TOKEN`；最后一条正常返回字面量 `/*`。不要把正常字符串中的注释标记当成 SQL 注释。

### 4. SQL Server DSN 脱敏

```bash
"$DBX" conn show sqlserver --config "$CFG"
```

命令成功，DSN 中 userinfo 和 `change password` 参数已掩码，输出不能包含 `OLD_DUMMY_SECRET` 或 `NEW_DUMMY_SECRET`。这条命令不会连接 SQL Server。

### 5. 同名结果列

```bash
"$DBX" query all 'SELECT 1 AS id, 2 AS id' --config "$CFG"
"$DBX" query all 'SELECT 1 AS id, 2 AS id, 3 AS id_2' --config "$CFG"
"$DBX" query all 'SELECT 1 AS id, 2 AS id' --config "$CFG" --format table
```

第一条行数据包含 `id=1,id_2=2`；第二条包含 `id=1,id_3=2,id_2=3`。列顺序仍按 SELECT 顺序，不能覆盖任何值。检查 JSON 的 `data.cols` 和 `data.rows` 使用相同名称；内部列统计的一致性由自动回归测试验证。

### 6. JSON 大整数

```bash
"$DBX" import file "$FIX/large.json" all imports --config "$CFG"
"$DBX" query all 'SELECT i,n,typeof(i) AS i_type,typeof(n) AS n_type FROM imports' --config "$CFG"
```

i 精确为整数 `9007199254740993`，n 为字符串 `9223372036854775808`。本例用 TEXT 列保留超界数值；真实数据库的目标列类型和精度仍决定最终存储。重复导入会增加行数，复测请用新夹具目录。

### 7. SQLite VACUUM

```bash
"$DBX" admin all VACUUM --config "$CFG"
"$DBX" query all 'SELECT count(*) AS n FROM users' --config "$CFG"
```

VACUUM 成功，n=3。admin 使用非事务执行，不承诺 `--max-rows-affected` 超限回滚；update、import、tx 的保护照常使用。

### 8. 非法格式不得有副作用

```bash
"$DBX" update all "UPDATE users SET name='changed' WHERE id=1" --config "$CFG" --format unsupported
"$DBX" schema all 'CREATE TABLE should_not_exist(id INTEGER)' --config "$CFG" --format unsupported
"$DBX" tx all --plan "$FIX/invalid-format-plan.json" --config "$CFG" --format unsupported
"$DBX" import file "$FIX/large.json" all imports --config "$CFG" --format unsupported
"$DBX" export table users all "$FIX/existing.csv" --config "$CFG" --format unsupported
"$DBX" query all 'SELECT name FROM users WHERE id=1' --config "$CFG"
"$DBX" query all "SELECT count(*) AS n FROM sqlite_master WHERE name='should_not_exist'" --config "$CFG"
"$DBX" query all 'SELECT count(*) AS n FROM imports' --config "$CFG"
cat "$FIX/existing.csv"
```

前五条均退出 1，stderr 报不支持的格式；后续核对 name=`original`、不存在的新表 n=0、imports 行数仍为第 6 项导入后的 1、文件仍为 `KEEP_THIS_FILE`。格式错误发生在连接解析之前，不依赖数据库成功连接。

## 范围

这份手册验证 CLI 保护和 SQLite 的真实结果。原手册中的真实 MySQL/PostgreSQL/Oracle/达梦/SQL Server、系统凭据库、Windows/Linux 和 Platform 安装仍需要各自环境实测。写入型 CTE 暂整体拒绝；不确定的引号转义和方言语法可能返回 `unknown_statement`。普通引号内反斜线、MySQL `#` 行注释、Oracle/达梦 `q/nq` 替代引号暂不支持；可改用标准注释或普通引号，PostgreSQL 支持显式 `E'...'`。
